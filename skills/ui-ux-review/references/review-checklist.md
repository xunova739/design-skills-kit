# UI/UX 审核检查表

只有在需要执行组合审核、或专职 Product Design 审核能力不可用时读取。不要逐项机械打勾；围绕用户主任务选择相关项。

## 1. 用户任务链

- 入口是否容易找到，名称是否是用户语言。
- 首屏能否回答“我在哪、能做什么、下一步是什么”。
- 主任务是否有不必要步骤、重复输入、来回跳转或隐藏前置条件。
- 主操作是否持续使用同一个名称，完成后是否明确告诉用户结果。
- 用户能否撤销、返回、重试或修正错误，而不丢失已填写内容。
- 高风险操作是否有足够确认，但没有重复确认拖慢高频工作。

## 2. 视觉质量

- 第一、第二、第三阅读层级是否清楚。
- 信息密度是否匹配场景：运营后台便于扫描，营销页突出核心价值。
- 字号、行高、对齐、间距、圆角、边框、图标和状态色是否有一致规则。
- 卡片、渐变、阴影、胶囊和动画是否承担信息作用，而不是模板装饰。
- 品牌、真实业务对象和关键数据是否在首屏可识别。
- 留意三张等宽卡、紫蓝光晕、所有内容都居中、无意义英文标签、装饰性编号等重复模式；结合品牌和任务判断是否缺乏理由，不能把明确要求或有信息作用的处理仅凭外观判为缺陷。

## 3. 交互成本

- 点击目标是否容易命中，移动端常用目标是否至少约 44x44 CSS 像素。
- 可点击元素是否看起来可点击；不可点击内容是否避免伪装成按钮。
- hover、focus、active、disabled、loading、success、error 是否可区分。
- 表单标签、必填、格式要求和错误信息是否在用户需要时出现。
- 错误是否说明发生了什么、如何修复、数据是否保留。
- 长列表、筛选、表格和批量操作是否支持高频重复使用，而不是每次重新定位。

## 4. 状态完整性

至少检查与当前任务相关的状态：

- 默认态
- 加载态
- 空态
- 成功态
- 失败态
- 禁用态
- 权限不足
- 网络慢或中断
- 旧数据、过期数据或并发变更

状态切换不能让布局突然跳动、滚动位置丢失、焦点消失或已输入内容被清空。

## 5. 响应式与可访问性

- 桌面和移动端是否都能完成同一核心任务。
- 文本放大、窄屏和系统缩放下是否重排，不能只缩小。
- 键盘是否能到达并操作核心控件，焦点顺序和焦点样式是否清楚。
- 图标按钮是否有可理解名称；表单控件是否有标签。
- 颜色不能成为唯一状态信号；文字和关键控件要有足够对比。
- 动画应尊重 `prefers-reduced-motion`，不能阻碍操作或引发眩晕。
- 截图只能发现风险；语义、读屏、键盘和动态通知必须通过实现或运行态验证。

## 6. 工程证据

- 主流程中是否有控制台错误、失败请求、重复请求或长时间无反馈。
- 页面是否横向溢出、遮挡固定操作、出现不可见弹窗或错误层级。
- 动态更新是否保留关键 DOM、滚动位置和输入焦点。
- 大型动效和 3D 依赖是否影响首屏、输入响应或移动端稳定性。

## 7. 严重度

- `P0`：已经观察到或由实现证据直接证明会阻断核心任务、误导关键决策、造成数据丢失、严重无障碍障碍或关键布局不可用。仅凭截图推测的交互困难不能定为 P0。
- `P1`：用户仍能完成，但明显费时、容易犯错、信任下降或主要视觉层级失效。
- `P2`：一致性、响应式或视觉细节问题，修复后明显提升完成度。
- `P3`：不影响主要使用的细微润色。默认合并到后续优化，不抢占 P0/P1。

## 8. 整改排序

先修任务结构和反馈，再修视觉层级，最后加动效和装饰。优先级按“影响用户数 x 发生频率 x 失败成本”判断，不按修改代码的容易程度判断。
